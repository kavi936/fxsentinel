# FXSentinel Project Structure

This document explains the organization of the FXSentinel project folder structure.

## Root Directory

The root directory contains only essential project files:
- `package.json` - Node.js dependencies and scripts
- `requirements.txt` - Python dependencies
- `vite.config.js` - Vite build configuration
- `eslint.config.js` - ESLint configuration
- `pyproject.toml` - Python project configuration
- `runtime.txt` - Python runtime version
- `.env` - Environment variables (not committed to git)
- Configuration files (`.gitignore`, `.dockerignore`, etc.)

## Folder Structure

### `/api`
Contains API endpoint handlers and webhook implementations. This includes serverless functions and API routes that handle external integrations.

### `/backend`
The main backend application directory containing:
- `app.py` / `main.py` - Main Flask application entry points
- `services/` - Backend service modules (AI analysis, alerts, economic calendar, etc.)
- `cache/` - Cached data files for economic calendars and other services
- Database files and session management
- Backend-specific configuration files

### `/src`
Frontend React application source code:
- `components/` - React components (Dashboard, Overview, Alerts, etc.)
- `contexts/` - React context providers (Auth, Notifications)
- `hooks/` - Custom React hooks
- `utils/` - Utility functions
- `config/` - Frontend configuration files
- `data/` - Frontend data files and templates
- `assets/` - Images and static assets used by the frontend

### `/public`
Public static assets served directly by the web server. This includes images, icons, and other files that don't need processing.

### `/docs`
All project documentation files:
- Setup guides (DEPLOYMENT_GUIDE.md, TELEGRAM_SETUP.md, etc.)
- Feature documentation (AI_ANALYSIS_*.md, ALERTS_*.md, etc.)
- System documentation and architecture notes
- Troubleshooting guides and fix summaries

### `/scripts`
Python utility scripts organized by purpose:
- Root level: Main utility scripts and entry points
- `utils/` - Setup, generation, and utility scripts (setup_*.py, create_*.py, etc.)
- `monitoring/` - System monitoring and health check scripts
- `tests/` - Test scripts (moved from root for organization)
- `deployment/` - Deployment-related scripts

### `/tests`
Test files and debugging utilities:
- `test_*.py` - Python test scripts
- `debug_*.py` - Debugging scripts
- `test_*.js` / `test_*.jsx` - JavaScript/React test files
- HTML test files and debugging pages

### `/data`
Data files used by the application:
- `raw/` - Raw CSV files and imported JSON data (economic indicators, calendar data)
- Root level: Processed JSON data files (alert history, market sentiment cache, etc.)
- Database files (economic_calendar.db)

### `/logs`
All log files from the application:
- Application logs (app.log, backend.log)
- Alert service logs
- Monitoring logs
- Process monitor logs

### `/deployment`
Deployment configuration and scripts:
- `Dockerfile` and `Dockerfile.worker` - Docker container definitions
- `Procfile` and `Procfile.worker` - Process definitions for deployment platforms
- `deploy_*.sh` - Deployment shell scripts
- `start_*.sh` - Service startup scripts
- `railway.json` - Railway deployment configuration
- Other deployment-related configuration files

### `/config`
Configuration files and credentials:
- `fxsentinel-firebase-adminsdk-*.json` - Firebase admin SDK credentials
- `env.example` - Example environment variables template
- `vercel.json` - Vercel deployment configuration
- Backup configuration files
- `VERSION` - Application version file

### `/temp`
Temporary files and session data:
- Telegram session files (`.session` files)
- Temporary recovery files
- Old build artifacts
- Files that can be safely deleted or regenerated

### `/backups`
Backup and recovery files:
- Code recovery JSON files
- Source code backups
- Important file backups that should be preserved

### `/overview-backup` and `/overview-online-backup`
Backup directories for the Overview component, containing previous versions of the component code.

### `/node_modules`
Node.js dependencies (automatically generated, not committed to git).

### `/dist`
Build output directory for the frontend (generated by Vite, not committed to git).

### `/__pycache__`
Python bytecode cache (automatically generated, not committed to git).

## File Organization Principles

1. **Separation of Concerns**: Frontend (`/src`), backend (`/backend`), and API (`/api`) are clearly separated.

2. **Documentation Centralization**: All markdown documentation is in `/docs` for easy reference.

3. **Script Organization**: Scripts are organized by purpose (utils, monitoring, tests, deployment) rather than being scattered in the root.

4. **Data Management**: Raw data files are separated from processed data, and database files are in appropriate locations.

5. **Log Management**: All logs are centralized in `/logs` for easier monitoring and debugging.

6. **Deployment Isolation**: All deployment-related files are in `/deployment` to keep the root clean.

7. **Configuration Security**: Sensitive configuration files are in `/config` and should not be committed to version control.

8. **Temporary Files**: Session files and temporary artifacts are in `/temp` and can be safely cleaned up.

## Maintenance Notes

- When adding new scripts, place them in the appropriate subdirectory of `/scripts` based on their purpose.
- New documentation should go in `/docs` with descriptive filenames.
- Log files in `/logs` can be rotated or cleaned periodically.
- Files in `/temp` can be safely deleted if needed (they will be regenerated).
- Always update this document when adding new major folders or reorganizing the structure.
